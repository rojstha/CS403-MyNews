# Deploying My News for $0

| Piece | Service (free plan) | What it does | Limits that matter |
|---|---|---|---|
| Database | **Neon** Postgres, Free plan | Stores articles, stories, summaries, run logs | Permanent free plan, no credit card. 1 GB storage per project, 100 compute-hours/month, compute sleeps after 5 idle minutes. Going over suspends or blocks writes until next month; it never charges. |
| API | **Render** free web service | Public HTTPS API the app reads; runs news collection when triggered | No card needed. 750 free instance hours/month, 512 MB, sleeps after 15 idle minutes, may restart at any time. Without a card on file, going over limits suspends instead of charging. |
| Hourly collection | **cron-job.org** | `POST /admin/collect?trigger=scheduled` at minute 0 of every hour | Free (donation-funded). 30-second request timeout; a job is disabled after more than 25 failures. |
| Keep the API awake | **cron-job.org** | `GET /health` every 10 minutes | Keeps Render from sleeping so the hourly call never times out; ≤744 h/month fits the 750 free hours (keep this the only free Render service). |
| AI summaries | **Ollama on the Mac** + launchd | `python -m app.ai_worker` at minute 5 of every hour writes summaries to Neon | Mac must be on, awake, and online. If it was asleep, launchd runs the job once on wake. |

Flow every hour: :00 cron-job.org → Render collects feeds into Neon → :05 Mac AI worker reads new stories from Neon, runs the local model, writes summaries → any phone reads `GET /stories` from Render.

**Where secrets live (never in GitHub):** the Neon connection string is pasted into Render's dashboard and into `backend/.env` on the Mac (git-ignored). `ADMIN_TOKEN` is generated by Render and pasted only into cron-job.org's header field. `.gitignore` excludes `.env`, logs and databases; `backend/tests/test_deploy_config.py` fails if a secret value is written into `render.yaml`.

---

## Step A: Neon database

1. Go to https://neon.com → **Sign up** → **Continue with GitHub** → authorize. Do **not** enter any payment details; the Free plan needs none.
2. Create a project: name `mynews`, Postgres version default, **Region: AWS US East 2 (Ohio)** (closest to Render's Ohio region). Click **Create project**.
3. On the project dashboard click **Connect**. Database `neondb`, role `neondb_owner`. Copy the **connection string** (starts with `postgresql://neondb_owner:...`). It contains the password: keep it private and never paste it into chat, code or GitHub.
4. Optional, saves free compute hours: **Branches → main → Compute → Edit** and set the size to the smallest (0.25 CU) if it shows a larger maximum.

## Step B: Render API

1. Go to https://dashboard.render.com → **Sign in with GitHub** → **Authorize Render**. Skip any billing prompt; if Render insists on a card before deploying a free service, **stop** and use the fallback at the end.
2. **New + → Blueprint** → connect the `rojstha/CS403-MyNews` repository (GitHub asks which repositories Render may access: choose **Only select repositories → CS403-MyNews**).
3. Render shows one service, `mynews-api`, plan **Free**. Fill in:
   - `DATABASE_URL`: paste the Neon connection string.
   - `CONTACT_INFO`: `https://github.com/rojstha/CS403-MyNews`
4. Click **Apply**. The first build takes ~3–5 minutes. When the service shows **Live**, open `https://<your-service>.onrender.com/health`; it should show `{"ok":true,...}`.
5. Service → **Environment** → reveal and copy `ADMIN_TOKEN` (for Step C only).

Fallback if the Blueprint flow asks for payment: **New + → Web Service** → the same repo → Root Directory `backend`, Runtime Python, Build `pip install -r requirements.txt`, Start `alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT`, Instance type **Free**, Region Ohio, and add the environment variables from `render.yaml` by hand (generate `ADMIN_TOKEN` yourself: `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`).

## Step C: cron-job.org schedules

1. Go to https://console.cron-job.org/signup, sign up with email, confirm the email.
2. **Create cronjob** #1 (keep-awake):
   - Title `My News keep awake`, URL `https://<your-service>.onrender.com/health`
   - Schedule: **Every 10 minutes**. Save.
3. **Create cronjob** #2 (hourly collection):
   - Title `My News hourly collect`, URL `https://<your-service>.onrender.com/admin/collect?trigger=scheduled`
   - Schedule: **Every hour** at minute **0** (custom: minute 0, every hour, every day).
   - **Advanced** tab: Request method **POST**; **Headers → Add**: key `X-Admin-Token`, value = the `ADMIN_TOKEN` from Render.
   - Save, then **Test run**: the response should be `202` with `"trigger": "scheduled"`.
4. After 1–3 minutes open `https://<your-service>.onrender.com/status`: the newest run should be `success` or `partial` with articles counted.

Evidence of the schedule: `/status` lists runs with `"trigger": "scheduled"` starting at :00 every hour, matching cron-job.org's execution history. (A test run from the console also counts as `scheduled`; note its time.)

## Step D: the Mac AI worker

1. Create `backend/.env` from the template and fill it in:
   ```bash
   cd ~/Downloads/myNews/backend
   cp .env.example .env
   open -e .env        # paste the Neon string after DATABASE_URL=, save, close
   ```
2. Make sure Ollama is running and the model is present: `brew services list | grep ollama` (should say `started`) and `ollama list` (shows `granite4.2:3b`).
3. Install the hourly job and run it once now:
   ```bash
   bash deploy/mac/install_ai_worker.sh
   launchctl kickstart gui/$(id -u)/edu.cs403.mynews.aiworker
   tail -f logs/ai_worker.log      # Ctrl+C to stop watching
   ```
   A successful pass prints a line like `{"status": "success", "summaries_generated": 3, ...}`.
4. Keep the Mac awake while plugged in: **System Settings → Battery → Options → "Prevent automatic sleeping on power adapter when the display is off" → On**. Lid closed = asleep (unless an external display is attached).
5. To stop it later: `bash deploy/mac/install_ai_worker.sh uninstall` and `brew services stop ollama`.

## Step E: build the app for the public API

```bash
cd ~/Downloads/myNews/flutter_app
flutter build apk --release --dart-define=API_BASE_URL=https://<your-service>.onrender.com
```

The APK is at `build/app/outputs/flutter-apk/app-release.apk`. Because it uses the public HTTPS address, the phone can be on any Wi-Fi or mobile data.

## Local development (no cloud)

```bash
cd backend
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
DATABASE_URL=sqlite:///./mynews.db .venv/bin/alembic upgrade head
DATABASE_URL=sqlite:///./mynews.db .venv/bin/python -m app.worker --trigger manual
DATABASE_URL=sqlite:///./mynews.db .venv/bin/uvicorn app.main:app --port 8000
.venv/bin/python -m pytest
```

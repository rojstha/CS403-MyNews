# Deploying My News

## Backend on Render (recommended)

`render.yaml` creates three things from the GitHub repository, all in the Oregon region:

| Resource | Role | Plan | Cost |
|---|---|---|---|
| `mynews-db` | PostgreSQL, persistent across restarts and deploys | free | $0, but **expires 30 days after creation** (14-day grace to upgrade, then deleted); 1 GB; no backups |
| `mynews-api` | FastAPI web service the app reads | free | $0; spins down after 15 idle minutes, ~1 minute to wake; 750 free hours/month |
| `mynews-hourly-collect` | Cron job: `python -m app.worker --trigger scheduled` at minute 0 every hour (UTC) | starter | billed per second of run time, **minimum $1/month**; each run takes about 10–60 s, so expect the $1 minimum |

The cron job is a separate process from the API, so collection happens even when nobody has the app open. Both services run `alembic upgrade head` before starting, so the schema is created and migrated automatically.

Secrets are never in the repository: `ADMIN_TOKEN` is generated by Render; `ANTHROPIC_API_KEY` and `CONTACT_INFO` are typed into the dashboard (`sync: false`); `DATABASE_URL` is injected from the database.

Steps:

1. Sign in at https://dashboard.render.com with **GitHub** and allow Render to access the `CS403-MyNews` repository.
2. **New → Blueprint** → choose `rojstha/CS403-MyNews`, branch `main`. Render reads `render.yaml` and lists the three resources.
3. Fill in the prompted values: `CONTACT_INFO` = `https://github.com/rojstha/CS403-MyNews` (both services). `ANTHROPIC_API_KEY`: leave empty for the first deploy (stories work; AI shows "unavailable") or paste the key.
4. Render asks for a payment method because the cron job is not free. Click **Apply**.
5. Wait until `mynews-api` shows **Live**; open `https://<api>.onrender.com/health`.
6. First collection: open the cron job → **Trigger Run**, wait 1–3 minutes, then check `https://<api>.onrender.com/status` and `/stories`.
7. After two full hours, `/status` should list two runs with `"trigger": "scheduled"` about an hour apart. Screenshot this and the cron job's run history for `docs/VERIFICATION.md`.

Adding the AI key later: set `ANTHROPIC_API_KEY` on **both** services (Environment tab → Save), then Trigger Run. Set a monthly spend limit in the Anthropic Console as a safety net.

## Local development

```bash
cd backend
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env            # edit values; SQLite by default
.venv/bin/alembic upgrade head
.venv/bin/python -m app.worker --trigger manual     # one collection
.venv/bin/uvicorn app.main:app --reload --port 8000
.venv/bin/python -m pytest
```

## Flutter app

```bash
cd flutter_app
flutter test
flutter build apk --release --dart-define=API_BASE_URL=https://<api>.onrender.com
# output: build/app/outputs/flutter-apk/app-release.apk
```

Install on the phone: enable Developer options → USB debugging, connect by USB, then `flutter install --release`, or copy the APK to the phone and open it (allow "install unknown apps"). Against a local server from the Android emulator use `--dart-define=API_BASE_URL=http://10.0.2.2:8000` with a debug build.

The release APK is signed with the debug key (fine for a class beta; not for the Play Store).

## Free alternative for the scheduler

If you do not want a paid Render cron job, the same command can run from a GitHub Actions schedule against the database URL (store it as a repository secret). GitHub may delay scheduled workflows by several minutes under load and disables them after 60 days without repository activity, so record the actual run times as evidence.
